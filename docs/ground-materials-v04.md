# Ground Materials v0.4

Developer Lab candidate for #63; production activation remains #60. The owner must review the composed scene against the original reference images before #59 is integration-ready.

The existing Three.js `MeshStandardMaterial` renders twelve regions of the original terrain. Every original triangle/position/normal is retained; regional UVs are padded and based on the same world coordinates. Height queries, navigation, building footprints, authored scenery and #56 water are unchanged. The separate flat path overlay is omitted only in regional mode; the same path/clearing/foundation fields now blend source material maps offline. The previous v0.2 ground remains available for comparison.

Sources are ambientCG Ground037 / Ground054 and Poly Haven mossy_rock / grass_path_2, all CC0. Their publisher albedo/diffuse, OpenGL normals and roughness supply the surface detail. There are no generated substitute images, authored GLSL effects or onBeforeCompile hooks. The path candidate was retained after a bounded village pilot; it does not contain a conspicuous painted path stamp. Palette saturation/tint, path weights, wet darkening and a continuous sampling warp are recorded in `src/config/RegionalGroundConfig.ts` and the pipeline. Broad colour fields no longer multiply albedo through green vertex colours.

Reproduce: download the exact source files listed in `public/ground-materials/v04/manifest.json` to `scratch/ground-source` (extract ambientCG 1K archives into their named subfolders), verify their SHA-256 values, then run:

```
node scripts/prepare-regional-ground.mjs
node scripts/qa/audit-regional-ground.mjs
```

Full-size 1K source maps are retained as inputs. The bake band-limits them to each tier's local pixel footprint at 2× oversampling (192/256px working grass-or-rock for Standard, 96/128px for Low), then blends a second rotated sample from the same source to reduce visible repetition. Rotated normal directions are transformed into the terrain tangent frame. These optimisations are justified by after-bake texel density, not an arbitrary blanket 256px reduction. The filtered maps are sampled in linear colour space; blended colour is encoded as sRGB, data maps remain NoColorSpace. Normals are normalized after blending and stored losslessly. Region maps use WebP: colour/roughness quality 90 and lossless normals. Texture gutters use shared world fields, not independent per-region random seeds. Native mipmaps and device-capped anisotropy (maximum 4) handle distant sampling. There is no height displacement.

Standard: 1024px maps with 32px gutters, 32 × 34.29 texels/m, 18,864,090 encoded bytes. Low: 512px maps with 16px gutters, 16 × 17.14 texels/m, 3,938,488 generated bytes (including offline diagnostic normal maps); the Low runtime downloads only 598,386 bytes of colour and roughness. Low omits the extra per-pixel normal layer; Standard retains all three source layers. Source repetition is 3m for grass/sand/path and 4m for rock; this is an authored choice, not an asserted publisher measurement. The previous 1024px world atlas had 8.83 × 12.8 texels/m and no albedo map.

Decoded RGBA8 plus full mip chains have conservative upper bounds of 192 MiB (Standard) and 32 MiB (Low colour/roughness runtime) for all regional maps. These are calculations, not measured GPU memory. Hidden baseline maps add a small one-time cost once that mode is rendered. Only one regional quality tier is retained at a time; obsolete and partial loads are disposed. GPU frustum culling limits rendered regions, but all maps in the chosen tier are loaded. Low should be used when Standard's detail is not needed. Actual mobile hardware acceptance is pending; mobile-format browser emulation is not a substitute.

See `docs/qa/ground-v04` for same-frame captures, source/output verification, seam samples and actual desktop measurements. Dusk is unavailable. The scenery still lacks the reference fjord walls, distant mountains, geometry reflections and warm night atmosphere; #63 does not claim to solve those separate #59 findings.
