## Proven dependencies and preserved updates

Each Human keeps only its last neutral fitting result. Reuse requires exact physical DNA, effective height, neutral bone factors/rest rig, body/source geometry identity and attribute versions, inverse/bind matrices, local body transforms/scales, fit encoding/revisions, module membership/output geometry, authored asset/binding revisions, eligibility, appearance fitting, sockets and installed hair/beard colour. Complete binding JSON snapshots detect in-place coverage/cage edits; a WeakMap shares one current snapshot per live binding rather than copying full cage strings per resident. Changed sources, geometry, scale, clothes, eligibility, external fitting edits or native-neutral inspection take the complete original fitting route.

Raw age, names and normalized heritage metadata alone are not neutral-fitting inputs. The existing parser can re-normalize heritage by one ULP; the optimization does not alter that parser or canonical DNA. It compares actual physical factors instead. Fresh DNA/profile/age, skin tint, hair appearance, animation cadence, pose shaping and animation time are still updated on every call. Actual hair/beard greying forces a refit. Children with changing body proportions refit, while invariant adult neutral geometry can remain owned by the same person. Elder pose/stride changes remain active and invalidate relevant gait/bounds work even when neutral garment geometry is invariant.

Gait sampling is reused only if both fitting and the exact motion/scale signature are invariant. Selection bounds use actual shape/fitting revisions and pose weights rather than age metadata alone, retaining the existing ordinary-animation bounds policy. Offscreen residents still receive their current age and pose; no visibility-dependent gameplay is introduced. Per-person geometry/material ownership and all existing disposal paths remain; there is no historical fitted-geometry or extra GPU-resource cache. `applyDNA(..., ..., {forceRefit:true})` retains the original complete path for comparison/fallback.

Canonical births/ages still use their existing Winter rules. Giving everybody a separate birthday tick would change age eligibility and saves; this change removes redundant presentation fitting without changing those rules. No body sources, authored clothing, textures, balance, life expectancy, animation policy, Core tick schedule, RNG, economics, careers or save schema changes.
