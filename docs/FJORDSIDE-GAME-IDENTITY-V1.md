# Fjordside — Game identity v1

**Official game title:** Fjordside  
**Working/internal repository name:** Pillagers  
**Working tagline:** Every life becomes a legend.

## Identity

Fjordside is a living Viking-world strategy and settlement simulation. The player influences the development and survival of a community rather than controlling one fixed protagonist. Individual residents are born with distinctive traits and heritage, grow older, form relationships, take occupations, and accumulate personal histories across generations. The resulting stories become the settlement's lore.

Conflict, raiding, trade and survival may be parts of this world, but **raiding is not the sole defining activity**. The central promise is to watch and shape a persistent community, where lives and choices have consequences.

## Voice and positioning

- Lead with settlement, generations, families and emergent stories; describe combat as one possible dimension rather than the entire premise.
- The name evokes a place to inhabit and revisit, grounded in a Nordic fjord landscape.
- Player-facing copy and UI remain in English.
- The tagline is a working creative direction, not a registered slogan.
- Preserve historical nuance; do not claim every simulated mechanic is historically accurate.

## Naming convention

- Use **Fjordside** in player-facing headings, game descriptions, splash/title screens, marketing and future lore framing.
- Keep **Pillagers** for the existing GitHub repository URL, historical issues, technical identifiers, paths, package names and integration references unless separately migrated and tested.
- Do not blindly replace historical documentation, code identifiers, or GitHub links. Existing issue references must remain valid.
- This identity decision does not rename the GitHub repository, npm package or application routes.

## Follow-up implementation

Audit current user-visible title strings, document headers, app metadata and onboarding copy for the old game name; change those in a dedicated, tested implementation PR. Preserve backwards compatibility for internal identifiers. Before a public release, perform a formal trademark, domain and storefront-name check.
