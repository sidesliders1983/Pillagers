# Gameplay Lab Clan Chronicle v0.1

Issue #37 delivers a deterministic Chronicle slice of #14; it does not close #14.

The English Chronicle appears as a collapsible left sidebar timeline. On narrow screens it stacks above the main controls. Winters appear newest first; entries within each Winter retain ledger order. Raw Events remains available from the same sidebar and shows the latest 100 technical events, with full history retained in exported JSON.

## Projection contract

projectChronicle(events, currentWinter?) is a pure public query. It reads only event fields, never current personas, browser time or random values. Each entry includes Winter, text, sourceEventIds, templateId, templateVersion and a routine marker. Sources disclosures show template/version and every contributing event ID.

Only supported templates produce text. The registry covers arrival/existing founding couples, occupations/autonomy, partnerships, births, ship choices, cattle assignment/slaughter, Farmyard activation/removal, houses/residences, specialization/upgrades, recorded maintenance debt/collapse, childcare and Food consumption. There is no death template because no actual death producer exists in the current simulation. Unknown or insufficiently recorded events remain raw-only.

ResourceProduced and CattleFoodProduced are aggregated separately by recorded canonical Winter. An aggregate appears at its first contributing event, retaining all contributing IDs in ledger order. Other meaningful events remain individual. Aggregation does not change timestamps or imply cause. Consumption retains the Winter recorded by its source event, even when recorded at a boundary. Economic entries are visually secondary.

Every Winter between the first recorded event and the current Winter is represented. Empty groups use the neutral, fact-free message No notable events were recorded this Winter; they do not synthesize a simulation event or Chronicle entry.

## Historical facts and compatibility

New semantic persona/family events capture people snapshots containing ID, name and age when recorded. Occupation events retain their existing name/age fields as well. House completion now records its household ID; residence assignment records residence kind. Additive facts preserve existing simulation rules and save format compatibility.

Older saves are not rewritten or backfilled from current personas. An old event with a recorded name uses it; when a participant name was never recorded, the Chronicle identifies that participant by the recorded resident ID. Missing facts never trigger a lookup into current mutable identity. Unknown event types remain Raw Events-only. No artificial meeting/marriage date is assigned to founding relationships.

Chronicle text is reconstructed from the saved ledger. It is not persisted as a second history, appended on repaint or generated by an AI service. Save/load, JSON import/export and repeated queries produce identical entries and provenance. Sidebar collapse/history-view selection is transient presentation state.
